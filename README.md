# EvaCode Bot

Telegram-бот для публикации объявлений в канале и передачи заявок от подписчиков команде менеджеров. Администратор отправляет боту текст, фотографию, видео или альбом, проверяет предпросмотр и подтверждает публикацию. Под опубликованным сообщением бот добавляет кнопку связи с консультантом, а обращения пользователей пересылает во внутренний чат, где менеджер может отметить заявку обработанной.

Проект написан на Python с использованием `aiogram 2.25.1`. Бот работает через long polling, хранит состояние диалогов в памяти процесса и не требует отдельной базы данных.

## Возможности

- доступ к публикации объявлений только для пользователей из списка администраторов;
- предпросмотр сообщения перед отправкой в канал;
- публикация текста, фотографий, видео и медиагрупп;
- добавление к публикациям кнопки «Связаться с консультантом»;
- передача обращения и данных клиента в чат менеджеров;
- защита от повторной отправки одной заявки одним пользователем в течение суток;
- отметка заявки как обработанной с указанием username менеджера;
- восстановление кнопки консультанта после редактирования зарегистрированной публикации;
- добавление менеджеров через системный Telegram-элемент выбора пользователя;
- запуск локально или в Docker Compose.

## Как работает бот

### Публикация объявления

1. Администратор открывает личный чат с ботом и отправляет `/start`.
2. Затем он отправляет текст, фотографию, видео или альбом.
3. Бот показывает предпросмотр и кнопки «Опубликовать» и «Отменить».
4. После подтверждения контент отправляется в канал, указанный в `CHANNEL_ID`.
5. К публикации прикрепляется кнопка обращения к консультанту.

Для альбома Telegram не позволяет прикрепить одну inline-клавиатуру ко всей медиагруппе, поэтому бот публикует альбом, а следом — отдельное сообщение с подписью и кнопкой.

### Обработка обращения

1. Подписчик нажимает кнопку «Связаться с консультантом» под публикацией.
2. Бот проверяет наличие публичного `username`. Если username не задан, пользователю предлагается обратиться к менеджерам напрямую.
3. Публикация и username клиента отправляются в чат `CHAT_ID`.
4. Менеджер нажимает кнопку «ОБРАБОТАТЬ».
5. Бот добавляет к сообщению отметку `Обработано: @username` и убирает клавиатуру.

Повторное обращение одного пользователя по одной и той же публикации блокируется в памяти процесса. Список таких нажатий очищается каждые 24 часа и также сбрасывается при перезапуске бота.

### Восстановление клавиатуры

Каждая созданная ботом публикация регистрируется в `src/data/published_posts.json`. Если Telegram присылает событие редактирования поста и кнопка консультанта отсутствует, бот добавляет ее снова. Реестр ограничен 1000 последними записями.

## Требования

- Python 3.10 (та же версия используется в Docker-образе);
- Telegram-бот, созданный через [@BotFather](https://t.me/BotFather);
- канал для публикаций;
- отдельный чат или супергруппа для обращений менеджеров;
- права бота на публикацию и редактирование сообщений в канале;
- права бота на отправку сообщений и медиа в чат менеджеров.

## Настройка Telegram

1. Создайте бота через `@BotFather` и сохраните токен.
2. Добавьте бота администратором в канал публикаций. Разрешите ему публиковать и редактировать сообщения.
3. Добавьте бота в чат менеджеров и разрешите отправку сообщений и медиа.
4. Узнайте идентификаторы канала и чата. Для каналов и супергрупп они обычно имеют вид `-100...`.
5. Добавьте Telegram ID хотя бы одного администратора в файл `src/data/admins.txt`, по одному ID на строку.

Пример `src/data/admins.txt`:

```text
123456789
987654321
```

Файл администраторов исключен из Git, поэтому его нужно создать отдельно в каждом окружении.

## Переменные окружения

Шаблон находится в `src/.env.template`. Создайте рабочий файл:

```bash
cp src/.env.template src/.env
```

Заполните значения:

```dotenv
BOT_TOKEN=1234567890:telegram-bot-token
CHANNEL_ID=-1001234567890
CHAT_ID=-1009876543210
```

| Переменная | Назначение |
| --- | --- |
| `BOT_TOKEN` | Токен Telegram-бота, полученный у `@BotFather`. |
| `CHANNEL_ID` | ID канала, куда публикуются объявления. |
| `CHAT_ID` | ID внутреннего чата, куда поступают обращения клиентов. |

Не добавляйте `src/.env` и реальные Telegram ID администраторов в репозиторий.

## Локальный запуск

Создайте и активируйте виртуальное окружение:

```bash
python3.10 -m venv .venv
source .venv/bin/activate
```

Установите зависимости:

```bash
python -m pip install --upgrade pip
pip install -r requirements.txt
```

Подготовьте конфигурацию:

```bash
cp src/.env.template src/.env
touch src/data/admins.txt
```

Заполните `src/.env` и `src/data/admins.txt`, затем запустите бот из корня проекта:

```bash
python src/app.py
```

При старте бот проверяет активный webhook. Если webhook настроен, он удаляется вместе с ожидающими обновлениями, после чего запускается long polling. Команда `/start` регистрируется автоматически.

Остановить процесс можно сочетанием `Ctrl+C`.

## Запуск в Docker

Перед запуском также создайте `src/.env` и `src/data/admins.txt`. Затем выполните:

```bash
docker compose up --build -d
```

Просмотр логов:

```bash
docker compose logs -f bot
```

Остановка контейнера:

```bash
docker compose down
```

`docker-compose.yaml` монтирует весь репозиторий в `/app`, поэтому файлы из `src/data` сохраняются на хосте после перезапуска контейнера.

## Локальные данные

Проект не использует СУБД. Служебные данные хранятся в `src/data`:

| Файл | Назначение |
| --- | --- |
| `admins.txt` | Telegram ID пользователей, которым разрешена работа с публикациями. Файл локальный и исключен из Git. |
| `published_posts.json` | Реестр опубликованных сообщений, необходимый для восстановления inline-клавиатуры. |
| `chats.txt` | Служебный список чатов из ранней версии проекта; в текущем основном сценарии не читается. |
| `manager_chat.txt` | Служебный файл из ранней версии проекта; актуальный чат менеджеров задается через `CHAT_ID`. |
| `logs.txt` | Зарезервирован под файловые логи; сейчас приложение пишет логи в stdout. |

В `utils/private_utils.py` также предусмотрен файл `swears.txt` для фильтра нежелательной лексики. Текущий основной сценарий этот фильтр не подключает. Если фильтр будет активирован, создайте `src/data/swears.txt`, записав по одному слову на строку.

## Архитектура и технические детали

- `aiogram.Dispatcher` создается в `src/loader.py` с `MemoryStorage`.
- Обработчики регистрируются при импорте пакета `handlers`.
- `AlbumMiddleware` собирает сообщения одной медиагруппы и передает их обработчику как единый список.
- Приложение запрашивает обновления `message`, `edited_message`, `channel_post`, `edited_channel_post` и `callback_query`.
- Публикации и обращения отправляются через Telegram Bot API.
- Логи выводятся в stdout в формате `дата уровень модуль: сообщение`.
- Состояния FSM и защита от повторных нажатий находятся только в памяти и не переживают перезапуск.
- Реестр публикаций записывается атомарно через временный JSON-файл с последующей заменой.

## Ограничения текущей реализации

- Бот рассчитан на один канал публикаций и один чат менеджеров.
- Горизонтальный запуск нескольких экземпляров не поддерживается: память FSM и защита от повторных заявок не являются общими.
- Автоматических тестов и миграций в проекте пока нет.
- Локальные файлы данных не подходят для конкурентной записи несколькими процессами.
- Для обращения к консультанту у клиента должен быть задан публичный Telegram username.
- При старте `skip_updates=True` отбрасывает обновления, накопившиеся пока бот был выключен.

## Диагностика проблем

### Бот не запускается

Проверьте, что `BOT_TOKEN` заполнен и файл `src/.env` доступен процессу. Ошибка валидации токена обычно означает пустое или неверное значение.

### Команда `/start` не отвечает

Убедитесь, что Telegram ID пользователя добавлен в `src/data/admins.txt`. Команда доступна только администраторам из этого файла.

### Публикация не появляется в канале

Проверьте `CHANNEL_ID` и права бота в канале. Боту нужны права на публикацию сообщений; для восстановления клавиатуры также требуется право редактирования.

### Заявка не приходит менеджерам

Проверьте `CHAT_ID`, членство бота в чате менеджеров и право отправлять сообщения и медиа. У клиента должен быть установлен публичный username.

### Бот получает конфликт polling

Telegram допускает только один активный polling-процесс для одного токена. Остановите второй локальный процесс или контейнер. Если для бота был настроен webhook, приложение удалит его при следующем старте.

### Кнопка не восстанавливается после редактирования

Проверьте, что сообщение было опубликовано текущей версией бота и присутствует в `src/data/published_posts.json`, а Telegram присылает боту обновления `edited_channel_post`. Также убедитесь, что у бота есть право редактировать сообщения канала.

## Разработка

После изменений можно выполнить базовую проверку синтаксиса всех Python-модулей:

```bash
python -m compileall -q src
```

При добавлении зависимостей фиксируйте их версии в `requirements.txt`. Секреты, персональные Telegram ID и локальные виртуальные окружения не должны попадать в Git.
